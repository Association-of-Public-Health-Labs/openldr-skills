# OpenLDR Report Skill — Design Spec

## Overview

A new `openldr-report` subskill that generates self-contained HTML report pages for visualizing OpenLDR analytics data. Data analysts can request HTML output from any OpenLDR skill, and the report opens locally in their default browser with an elegant dark dashboard design featuring charts and tables.

## Data Sources

- **Primary:** API responses from `openldr-query-api` and database query results from `openldr-explore`
- **Secondary:** Any structured/tabular data produced by other OpenLDR skills during a conversation

## Trigger & Invocation

### How it's triggered

Users can request HTML reports in two ways:

- **Upfront:** "show me VL suppression by province as an HTML report"
- **After results:** "generate an HTML report for this"

**Detection keywords:** "generate HTML report", "show in browser", "visualize this", "as HTML", "open in browser", "export as HTML report"

### Invocation paths

**Path A — Upfront request:**
1. `openldr` routes to the appropriate data skill (`openldr-query-api` or `openldr-explore`)
2. The data skill fetches the data
3. The data skill recognizes the HTML request and invokes `openldr:report`
4. `openldr:report` generates the HTML, saves it, opens browser, shares link

**Path B — After results:**
1. `openldr` routes directly to `openldr:report`
2. `openldr:report` uses the data already present in the conversation context
3. Generates HTML, saves it, opens browser, shares link

### Data passed to `openldr:report`

- The structured data (JSON from API or query results)
- The report title (derived from the query/endpoint)
- The date range (if applicable)
- The data source description (endpoint URL or SQL query)

## Report Layout

Dark dashboard theme (`#0f172a` background). Sections top to bottom:

### 1. Header Bar
- "OpenLDR Report" label (left, sky blue, uppercase)
- Report title derived from the query (left, white, bold)
- Date range and generation timestamp (right, muted)

### 2. KPI Summary Cards (conditional)
- Row of 2-4 metric cards — only when data has aggregatable metrics
- Color-coded values:
  - Blue (`#38bdf8`) — primary metrics
  - Green (`#4ade80`) — positive indicators
  - Amber (`#fbbf24`) — neutral/TAT
  - Red (`#f87171`) — alerts
- Card background: `#1e293b`, border: `#334155`
- Auto-detected from data patterns: `total_*`, `*_rate`, `*_percentage`, `average_*`

### 3. Chart Area (conditional — based on data shape)
- Auto-selected chart type based on data detection rules (see below)
- Chart.js via CDN (`<script>` tag)
- Dark theme: dark canvas background, light grid lines, vibrant data colors

### 4. Data Table (always present)
- Full dataset in a styled table
- Alternating row colors (dark shades: `#1e293b` / `#0f172a`)
- Sortable columns via inline JavaScript
- Number formatting (commas for thousands, percentage symbols)
- Header row: `#334155` background

### 5. Footer
- "Generated by OpenLDR Skills" attribution
- Data source info (API endpoint URL or SQL query used)
- Generation timestamp

## Data-to-Visualization Mapping Rules

Detection rules applied in order:

| Data Pattern | Chart Type | Example |
|---|---|---|
| Has a date/month column + numeric column | Line chart | `tested_samples_by_month` |
| Has a categorical column + single numeric column, ≤15 categories | Vertical bar chart | `suppression_by_province` |
| Has a categorical column + single numeric column, >15 categories | Horizontal bar chart | `tested_samples_by_facility` |
| Has a categorical column + multiple numeric columns | Stacked/grouped bar chart | `tested_samples_by_age` with gender |
| Has 2-5 categories representing parts of a whole (~100%) | Doughnut chart | `by_gender` distribution |
| Only 1-2 rows of aggregate data | KPI cards only, no chart | `header_indicators` |
| Raw tabular data with no clear aggregation | Table only, no chart | Exploratory query results |

## Chart.js Integration

- Loaded via CDN: `<script src="https://cdn.jsdelivr.net/npm/chart.js"></script>`
- All CSS inline in the HTML file
- Data embedded as a JavaScript object in a `<script>` block
- Single self-contained `.html` file — no server needed, opens via `file://` protocol

## `open-report.sh` Helper Script

**Responsibilities:**
1. Accept an HTML file path as argument
2. Generate filename with timestamp if not specified: `openldr-report-YYYYMMDD-HHMMSS.html`
3. Save to target directory (default: current working directory)
4. Open in default browser:
   - Linux: `xdg-open`
   - macOS: `open`
   - WSL: `wslview` or `cmd.exe /c start`
5. Print the file path and `file://` URL to stdout

**Usage:**
```bash
# Save to current dir and open
scripts/open-report.sh report.html

# Save to specific directory
scripts/open-report.sh --output-dir /path/to/reports report.html

# Custom filename
scripts/open-report.sh --name "vl-suppression-march" report.html
```

**Credential handling:** Not needed — this script doesn't access databases or APIs.

## Changes to Existing Skills

### `openldr/SKILL.md`
Add routing entry:

| User Intent | Skill to Invoke |
|---|---|
| Generate HTML report, visualize data in browser, export as HTML | `openldr:report` |

### `openldr-query-api/SKILL.md`
Add note in Phase 4 (Explain Results): if the user requested HTML output, invoke `openldr:report` with the API response data, endpoint info, and date range.

### `openldr-explore/SKILL.md`
Add similar note after synthesizing answers: if the user requested HTML output and the answer includes tabular/structured data, invoke `openldr:report`.

## File Output

- **Default location:** Current working directory
- **Default filename:** `openldr-report-YYYYMMDD-HHMMSS.html`
- **Custom location:** User can specify output directory or filename
- **Delivery:** After generation, the skill prints the file path and opens it in the default browser automatically
